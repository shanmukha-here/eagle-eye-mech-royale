# Running the local placement board

Run `./localboard.sh` from a full Git checkout. The runner needs Linux, Python 3.9 or later, a C compiler, and the unpacked official kit. Set `MECHFIGHT_KIT` if the kit is outside `../brief/kit/mechfight-kit`. The runner retrieves fixed policies from Git history and builds a geometry library in the result cache. The submitted bot needs neither Git nor the evaluator.

The default compares the candidate with `6c7bb86` on 200 development and 200 held-out starts in **each** of three fields. Each game has 16 mechs and earns 16 minus finishing place. The report gives the mean score, counts at each place, and a two-sided 95% interval on the mean. The interval on the score difference pairs the two policies by seed, including starting slot, roster and resources. A difference can be estimated more precisely than either score on its own.

- The practice field simulates a squad with shared sightings and tiered activation. Its fixed mix includes the kit starter, earlier entries, hunters, a camper, looters and zone-edge policies. With a private ledger at `../CALIBRATION.md`, the primary prediction is the incumbent’s official score plus the paired gain times the median recorded board/raw ratio. The raw-times-median comparator is also printed. Use `--calibration PATH` or `--ratio NUMBER` to override.
- The strong field plays independent free-for-alls. Its 15 opponents are six copies of `c9901fa`, four of `8165f67`, two of `376dc9c` and three of `30cd616`. Every bot has its own state and sees its own observation. Its mean is in placement points and has no official calibration.

The qualifying field mixes five archived submitted policies, the kit starter, three hunters, the archived equipment and circle entries, one laser scout, two cube farmers and a ring camper. Each actor plays independently. Evaluate it with `--pool qualifiers`. The per-match cache includes elapsed time, zone phase and cause of death, quiet travel, actual enemy sight with occlusion, and any switch counts emitted by the subject.

Use `./localboard.sh --native --split p7screen --workers 48` for development. Use `--split p8select` for qualification-policy selection. Freeze the policy before using `--split p8test` or the default command. Request a report with `--report PATH`. Select a single field with `--pool practice` or `--pool strong`. Historical splits and `--ffa` remain available to reproduce older comparisons. Set `--models phase1 phase2 phase3 phase4 phase5 candidate` to score all five submitted references.

Each subject runs through the official JSON-lines protocol. The runner uses Docker if installed. Use `--docker` for a release check. Each subject gets one CPU, 512 MiB, no swap or network, UID 65534, a read-only filesystem, a 64 MiB temporary filesystem and a 128-process limit. In native mode, the runner pins each match to one CPU and caps the subject process address space at 512 MiB. Both modes run the kit checker before the matches. A late decision coasts, then idles. A crashed subject keeps its eventual place. Seeds and game logic are deterministic. Wall-clock deadline misses can change outcomes under contention. The separate native and Docker caches live outside the checkout. Pass `--cache PATH` for a cold run.

The simulator uses the kit map and game constants. It advances physics at 20 Hz and subjects at 10 Hz. Squad activation thresholds, opponent tactics, spawn distributions, collision rasterization and some weapon and drone interactions approximate the private server. The intervals quantify variation across local seeds. The competition also differs in its opponent population and runs only 48 practice matches.

Run `python3 -B check_localboard.py` for rules, schema and process-failure checks. Pass `--replay PATH` with a public mechanics-v2 exhibition to check the zone schedule and spawn heights. The checkout does not include the map, exhibitions or competition data.

To reproduce the initial seven individual switches and their combination, run `python3 study.py screen` from the checkout. Run `OPENBLAS_NUM_THREADS=1 python3 study.py tune` for the constrained 40-treatment CMA-ES search. Tuning uses NumPy 1.26.4 on the evaluation host. The bot and its Docker build use only the Python standard library. Feasible treatments have an anchored practice forecast of at least the incumbent score. Their objective is the sum of strong and qualifying mean placement. Neither command accesses the release seeds. Use `--revision` to study another compatible policy. Run on the allowed CPU set for the host.

The archived stealth policy in commit `04cd061` reconstructs a 6 m cover grid from the mounted arena during the hello handshake. Each cell records obstruction in eight directions and canopy. Navigation also checks wall clearance and possible roof landings. This keeps the public checkout independent of the competition map files.
